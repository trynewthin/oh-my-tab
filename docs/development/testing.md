# 测试指南

[返回文档中心](../README.md)

## 测试分层

| 目录             | 内容                                             |
| ---------------- | ------------------------------------------------ |
| `tests/unit/`    | 存储、备份、导入、领域计算和缓存等纯逻辑测试     |
| `tests/e2e/`     | 新标签页、设置、搜索、组件和拖拽等浏览器交互测试 |
| `tests/helpers/` | 测试共用的模块加载与存储辅助代码                 |
| `tests/results/` | Playwright、WebDAV 等测试生成的临时产物          |

`tests/results/` 已加入 Git 忽略。截图、失败现场和验证 JSON 都必须写入该目录，不在根目录创建 `artifacts`、`test-results` 或 `playwright-report`。

## 常用命令

| 命令                     | 用途                                                    |
| ------------------------ | ------------------------------------------------------- |
| `npm run check`          | 检查格式、Lint、类型、架构、单元测试，并构建产品官网    |
| `npm run build`          | 类型检查并构建扩展                                      |
| `npm test`               | 基于已有构建运行 Playwright 端到端测试                  |
| `npm run test:extension` | 在真实扩展环境验证新标签页入口、语言、浏览器 API 和 CSP |
| `npm run test:webdav`    | 验证 WebDAV 连接、上传、恢复和并发保护                  |
| `npm run dev`            | 启动扩展和 WebDAV 集成验证使用的开发服务器              |
| `npm run website:dev`    | 启动产品官网开发服务器                                  |

提交前至少运行与改动直接相关的测试，并运行 `npm run check`。修改共享组件、持久化或构建入口时，再运行 `npm run build` 和 `npm test`；修改扩展入口、权限或 CSP 时，补充 `npm run test:extension`。

端到端测试使用 `vite preview`，首次运行或源码变化后先执行 `npm run build`。

## 环境要求

Playwright 优先使用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`，macOS 上默认尝试 Google Chrome，其他环境可通过 `npx playwright install chromium` 安装浏览器。

WebDAV 集成验证需要 Docker。先在一个终端运行：

```bash
npm run dev
```

再在另一个终端运行：

```bash
npm run test:webdav
```

可以用 `WEBDAV_TEST_APP_URL` 指定待验证的开发页面地址。脚本使用临时容器、临时浏览器配置和独立扩展副本，结束后自动清理这些运行环境。

## 编写原则

1. 单元测试覆盖稳定的输入输出和边界条件，不复刻实现过程。
2. 端到端测试从用户可见行为断言，避免依赖无意义的 DOM 层级。
3. 共用准备逻辑放在 `tests/helpers/`，不要在多个测试文件复制存储初始化。
4. 需要截图时使用 Playwright 的 `testInfo.outputPath()`，让结果自动进入统一目录。
5. 测试失败应保留足以定位问题的结果，成功运行不生成长期维护的文档素材。

## 标签默认动态效果

“标签”设置中的“新标签默认动态效果”每次开启或关闭时先持久化默认值，再询问是否同时更新已有标签。开启后选择“仅新标签开启”或关闭确认框，只让之后通过编辑器、快捷收藏及书签导入创建的独立标签默认开启动态效果；标签加入文件夹时按文件夹整体开启动态效果，因为文件夹内标签只支持统一开启或关闭。选择“全部开启”会立即为当前所有独立标签和含标签的文件夹重新开启动态效果。关闭后选择“仅新标签关闭”或关闭确认框，不修改现有标签；选择“全部关闭”会立即关闭所有独立标签和含标签文件夹的动态效果。文件夹的状态只控制内部标签，文件夹背景在卡片、编辑预览和展开面板中均保持静态。

标签及文件夹内标签的右键菜单不提供刷新图标；图标操作统一放在编辑弹窗中。未设置自定义图标时直接刷新网站图标；已设置自定义图标时先弹窗确认，取消不修改图标，确认后重新请求网站图标，且仅在刷新成功后清除自定义图标。上传仅接受不超过 2 MB 的 PNG、JPEG 或 WebP；选择文件后必须在正方形裁剪弹窗中确认，取消不修改图标，确认后在本机重新编码为 128×128、最大 64 KiB 的 WebP。自定义图标随标签持久化，在标签移入或移出文件夹时保留，并进入 ZIP/WebDAV 备份。

## WebDAV 同步

连接成功后保存完整连接信息（含密码）、随机设备标识、快照保留数量及同步基准；旧版只保存地址和用户名的记录需要重新输入一次密码。点击状态灯可修改连接和保留数量，点击删除会弹窗确认，确认后清除本机连接记录；取消或关闭弹窗保留连接。连接检测成功为绿灯，否则为红灯；检测发生在打开同步设置、重新连接及同步前。

首次同步时，远端有备份就直接使用远端并建立同步基准，不受上传设备或变更幅度影响；远端为空才上传本机。内容与最新版本相同时记录基准而不重复传输。普通同步准备上传的内容若已存在于其他保留快照中，则不上传、不更新时间、不改变最新版本或本机同步基准；已有普通重复记录在后续同步时按内容校验值合并。“同步快照”弹窗右上角的“手动同步”始终上传当前本机数据并新建快照，允许内容相同的手动快照并存。建立基准后，远端仍是上次同步的版本时上传本机变化。远端出现其他设备的新版本时，在本机未变更且远端变化较小时下载，否则选择保留本机或远端。差异按书签、组件及设置项计算，超过 30% 或删除至少 5 项视为较大变更。

远端 `oh-my-tab-sync.json` 索引引用不可变的 `oh-my-tab-snapshot-<UUID>.zip`。索引使用强 ETag 条件写入，成功后才清理超出数量的快照；清理失败保留待清理名单并提示重试。默认自动保留 5 个未改名的快照，可配置 1–100 个，下次上传时应用。已改名的快照额外保留，不计入自动保留数量。旧版 `oh-my-tab.zip` 可作为首次同步来源；新版索引建立后以索引为准，旧客户端不能参与新版同步。连接凭据不进入 ZIP。

冲突弹窗展示所有保留快照的名称，名称默认为时间；内部差异只用于同步方向判断，不显示在列表中。“同步快照”设置项通过对话框读取同一份列表，可在关闭按钮左侧手动同步。应用快照与删除快照均需二次确认；取消或关闭不修改数据。确认应用后重新读取并校验对应远端文件，只覆盖当前设备的数据，不改变远端列表。删除使用索引 ETag 防止并发覆盖，先移除引用再清理文件；内容相同的手动快照按记录单独删除。删除最新快照后使用上一份作为远端最新版本；删完全部快照后保留空索引，避免旧版备份重新出现，下次同步会上传本机数据。

回归覆盖应包含：刷新后恢复配置、错误密码、状态灯、两个设备交替上传下载、较大变更弹窗、取消后两端不变、并发上传拒绝、保留数量与清理失败、删除后不再恢复连接、旧版备份迁移。浏览器及端到端检查遵循仓库 `AGENTS.md` 的逐次授权要求。

快照的 `name`、`protected` 与 `manual` 标记保存在远端索引中。只有实际修改名称才标记保留；之后即使改回时间名称，也不自动取消保留。普通去重优先保留已改名的副本，手动删除仍需二次确认。写入保留标记后使用第 2 版索引；创建强制手动快照后使用第 3 版索引，让不支持相应规则的旧客户端拒绝操作，防止误清理；所有设备应更新到支持该索引的版本。单文件备份重命名时复制为不可变快照并登记索引，保留原文件；后续读取以索引为准。
