# 核心原则

保留不可廉价重建的知识，提供有明确用途的行为引导。
约束必要的边界，不替执行者预先决定所有解法。
以足够清楚为下限，以没有冗余为目标；不追求最短。

# 写作规则

1. 先确定用途
   从任务上下文判断：谁会在什么场景读取它，它帮助完成哪个理解、判断或动作？
   找不到具体用途的内容，不主动新增。只对影响正确性的关键缺口提问。

2. 先复用，再新增
   定向检查相关文档、技能、代码、测试与配置，优先更新已有权威来源。
   可低成本获取且表达充分的知识，提供准确入口，不再维护副本。
   引用不足以解释意图时，补充必要背景，而不是要求读者自行猜测。

3. 根据作用选择载体
   文档承载事实、约定、决策理由与使用说明。
   技能承载特定场景下的行为引导：何时介入、改变什么、何时完成或退出。
   仅仅复述一项系统能力，不足以新建技能；只有确实需要时才拆分文件。

4. 优先记录无法从表面恢复的信息
   写清隐含的业务语义、取舍理由、反直觉例外和不可擅自改变的边界。
   区分已核实事实、现行约定、建议与未知；不把单次成功写成普适规则。
   对容易变化或影响重大的结论，保留来源、定位或适用条件，不编造依据。

5. 给出判断依据，避免接管解题
   优先说明目标、必要背景、边界与完成标准，而非穷举执行步骤。
   当顺序、方法或具体操作确实影响正确性、安全性或复现时，保留必要流程。
   示例用来消除歧义，不应被默认为唯一解法。

6. 控制影响范围
   全局上下文只放跨任务必要的约定与入口；局部知识按需读取。
   行为规则写明适用条件，不把局部经验升级为所有任务的默认要求。
   可机械检查的规则优先由测试或工具保障；未经授权不改动这些机制。

7. 按作用压缩，不按字数压缩
   删除不改变理解或行为的套话、重复说明和无依据的预防性要求。
   保留避免误解所需的解释、例外和示例，尤其是低频但后果重大的边界。
   不强制套用固定章节，不为结构完整补写没有价值的内容。

# 交付前检查

用一个具体使用场景检查：读者能否找到它、理解它，并据此作出正确判断或行动？
对于技能，另检查它是否会干预不该介入的任务，以及任务完成后能否退出。
核查关键事实与引用；区分实际验证和推演，未验证的效果不得宣称已证实。

默认交付可直接使用的正文，仅另列影响使用的关键未决项。
不附带新的治理体系，不自行扩建文档目录，未经授权不修改文件。
